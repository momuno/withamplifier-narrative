The three needs

You need three things from your AI framework.

You picked a framework. It got you to a demo fast. Then the model landscape shifted, or you needed production-grade behavior, or your teammate asked how to reuse your setup.

01

Portability

The model you chose isn't the model you need.

You built on one SDK. A different model turned out to be better for your use case. The model landscape shifts quarterly. Switching means rewriting your agent logic, your tool interfaces, your error handling — not because the problem changed, but because the framework assumed your provider was permanent.

With Amplifier

Providers are modules. Five methods. Switch by changing one YAML line. Run multiple simultaneously. Your tools, hooks, and orchestrator never know which model is answering — because the kernel has zero vendor code.

Switch provider: change one line

providers: - module: provider-anthropic # swap to provider-openai config: model: claude-sonnet-4-5 # swap to gpt-4o # Or run both simultaneously providers: - module: provider-anthropic config: { model: claude-sonnet-4-5 } - module: provider-openai config: { model: gpt-4o }
02

Control

You can see what's happening. You can't change it.

Your framework gives you an agent loop that works — until you need the agent to pause for human approval, consult a second model for verification, or handle long conversations differently than silent truncation. The two most important behaviors — how the agent reasons and what it remembers — are the ones you need to own.

With Amplifier

The agent loop is a module. Memory is a module. Hooks are a control plane with five actions: continue, deny, modify, inject_context, ask_user.

inject_context means hooks participate in the agent's reasoning, not just the logging.

A hook that teaches — not by blocking, but by injecting context

async def commit_convention_hook(event, data): if event != "tool:pre" or data.get("tool_name") != "bash": return HookResult(action="continue") command = data.get("tool_input", {}).get("command", "") if not command.startswith("git commit"): return HookResult(action="continue") if not re.match(r'git commit -m ["\\']?(feat|fix|docs)', command): return HookResult( action="inject_context", context_injection="Commit messages must follow " "conventional format: feat|fix|docs|refactor: description", ) return HookResult(action="continue")
03

Composability

What you build doesn't travel.

You built a great setup: the right model, the right tools, a custom hook that enforces your team's standards. Your teammate wants the same but with a different model and an extra tool.

How do you share it? Copy the config. Manually edit it. Keep two copies in sync. No inheritance. No override semantics. Software engineering solved this with package managers decades ago. AI development tooling hasn't caught up.

With Amplifier

Bundles compose modules with algebraic merge rules. Inherit, override, extend. Your teammate takes your bundle, swaps the provider, adds a tool — no duplication.

Bundle inheritance: composition, not configuration

# Your team's bundle: 14 lines, a complete system bundle: name: my-team-platform version: 1.0.0 includes: - foundation # 30+ agents, 7 tools, streaming UI - python-dev # linting, type-checking, LSP providers: - module: provider-anthropic config: { model: claude-sonnet-4-5 } hooks: - module: hooks-approval

Your teammate extends it — three lines changed

includes: - my-team-platform # everything inherited providers: - module: provider-openai # swapped config: { model: gpt-4o } tools: - module: tool-browser-test # added

The architecture

A kernel that provides mechanisms. Everything else is a module you own.

2,600 lines of Python. Zero decisions about models, loops, tools, or memory. The kernel loads modules, manages sessions, dispatches events, and resolves hook precedence. That's it.

"Could two teams want different behavior? Then it's a module, not the kernel."

Door 2 · Hours

Intercept

Write hooks that control agent behavior. Learn the difference between monitoring and a control plane.

A hook that teaches

Instead of rejecting a bad commit message, inject_context teaches the agent the convention. The agent corrects itself. No retry loop, no error — guidance woven into reasoning.

async def commit_convention_hook(event, data): if event != "tool:pre" or data.get("tool_name") != "bash": return HookResult(action="continue") command = data.get("tool_input", {}).get("command", "") if not command.startswith("git commit"): return HookResult(action="continue") if not re.match(r'git commit -m ["\\']?(feat|fix|docs)', command): return HookResult( action="inject_context", context_injection="Commit messages must follow " "conventional format: feat|fix|docs|refactor: description", ) return HookResult(action="continue")

A hook that guards

Before any write to a production file, ask_user pauses execution and presents the human with a choice. Allow once, allow always, or deny. The agent waits.

async def production_guard(event, data): if event != "tool:pre" or data.get("tool_name") not in ("Write", "Edit"): return HookResult(action="continue") file_path = data.get("tool_input", {}).get("file_path", "") if "/production/" not in file_path: return HookResult(action="continue") return HookResult( action="ask_user", approval_prompt=f"Allow write to production file: {file_path}?", approval_options=["Allow once", "Allow always", "Deny"], approval_default="deny", )

Door 3 · A day

Replace

Write modules that swap framework layers. Learn that the kernel has no opinions and the contracts are real.

Replace the memory

The default context stores every message. Your context module can summarize old conversations, compress tokens, or retrieve from a vector store. Implement five methods. The kernel doesn't know the difference.

class SummarizingContext: """Compress old context via LLM summarization.""" def __init__(self, summarizer_provider): self.messages = [] self.summarizer = summarizer_provider async def add_message(self, message): self.messages.append(message) async def get_messages_for_request(self, token_budget=None, provider=None): if len(self.messages) < 50: return list(self.messages) old, recent = self.messages[:-20], self.messages[-20:] summary = await self._summarize(old) return [{"role": "system", "content": summary}] + recent async def get_messages(self): return list(self.messages) async def set_messages(self, messages): self.messages = list(messages) async def clear(self): self.messages = []

Replace the agent loop

The default orchestrator runs a single-model loop. Yours can consult two providers, pick the best answer, run a verification chain, or implement tree-of-thought. The orchestrator contract is one method: execute.

class VerificationOrchestrator: """Consult two providers. Pick the better response.""" async def execute(self, prompt, context, providers, tools, hooks): await context.add_message({"role": "user", "content": prompt}) messages = await context.get_messages_for_request() request = ChatRequest(messages=messages, tools=get_schemas(tools)) primary = providers["anthropic"] verifier = providers["openai"] response_a, response_b = await asyncio.gather( primary.complete(request), verifier.complete(request), ) best = self._pick_best(response_a, response_b) await context.add_message({"role": "assistant", "content": best.text}) return best.text
